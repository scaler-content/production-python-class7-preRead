5. pytest done properly, and five kinds of check

You have written pytest checks since Class 2. Today we make them easier to read when they fail. Two features do most of the work. Parametrize runs one check for many inputs, and names each run by its input. A fixture is set-up that pytest builds for a test that asks for it by name, and tidies up afterwards. Think of a stage hand who puts the chairs out before the show: the actors only say, "I need a chair".

One check, five inputs, five named results (you will write this in class)
@pytest.mark.parametrize("raw", ["1.250", "1,250.00", "NaN", "Infinity", "-3.00"])
def test_amount_refuses_anything_but_two_decimal_places(raw):
    with pytest.raises(MalformedRecord, match="must look like 19.99"):
        parse_amount(raw)

A loop inside one test stops at the first failure and does not say which value failed. Parametrize makes five tests, so all five run, and a failure shows its input in its name, such as [19.99]. The match= part checks the reason in the message, so a refusal for the wrong reason does not pass.

6. A bug becomes a test, before it becomes a fix

Here is a rule that saves hours: when you find a bug, write the test first, and watch it fail. A test you have never seen fail may be a test that cannot fail. Then fix the code, and watch the same test pass. A test written for a failure we have really seen is a regression test: it keeps that failure from coming back. Think of a bandage with a date on it.

We have a real one to work on. In Python, the pattern \d means "any digit", and that includes digits from other scripts. So the Workbench, written with \d since Class 2, accepted some numbers it should have refused:

The bug you will see in class
parse_units('١٢')   ->  12
parse_amount('١٩.٩٩') ->  Decimal('19.99')

Those are Arabic-Indic digits. The fix is small: write [0-9] instead of \d. The point of the class is the order of the steps.

7. A check on every pull request, and a fake model for the AI part

Branch, pull request, checks, merge

You work on a branch, a copy of the project where changes are safe. You open a pull request, a page that asks to merge the branch into main and keeps the change, the checks and the discussion together. Continuous integration (CI) is a service that runs the checks on a clean machine every time. Ours is GitHub Actions. Think of a fresh kitchen for every recipe test: if it works there, it does not depend on what is left in yours.

Fake models

A model is the one part we do not control. Its answer can be good, cut off, off-list, late, a refusal, or a polite "I cannot tell". A fake model is a small function that returns exactly the reply we script, and no key or network is needed. In class one table covers all six outcomes, and it finds a real waste: a refusal used to trigger a pointless repair call.
